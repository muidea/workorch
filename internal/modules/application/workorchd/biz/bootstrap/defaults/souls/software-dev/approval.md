# 软件开发审批

高风险操作前请求审批。普通代码修改、构建、测试、非破坏性重构，以及为满足当前 Goal/DoD 的低风险工作区内依赖元数据修复（如当前 workspace 内 manifest、checksum、lock、requirements 等配套文件的最小更新），不需要主动请求人工审批，可由自动治理策略评估。

## 触发场景
- 数据库 schema 变更或数据迁移
- 生产环境部署、远端写操作或发布包
- 破坏性 API 变更
- 删除或重命名公开接口
- 第三方依赖升级带来许可证、安全、供应链或大规模锁文件变更风险
- 可能删除用户数据、项目历史或不可恢复文件的操作

## 低风险依赖元数据边界
- 仅限当前 workspace 交付目录内、为满足当前 Goal/DoD 而进行的最小配套元数据修复
- 仅限 manifest、lock、checksum、requirements 或等价依赖声明文件
- 只要涉及远端发布、生产环境、凭证、外部系统写入、大规模升级或不确定供应链影响，仍应走人工审批

## 审批格式
- reason: 操作内容和风险评估
- action: 待审批的具体操作
- context: 影响范围、替代方案和回滚方案

## 禁止
- 不要用 Approval 代替普通信息补充；缺信息应使用 Decision
- 未获批准前不要执行高风险操作
