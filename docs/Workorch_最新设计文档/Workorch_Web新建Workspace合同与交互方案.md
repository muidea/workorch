## 1 用户看到的新建完成

| 里程碑 | 页面依据及文案 | 允许的下一步 |
|---|---|---|
| M1 容器已创建 | 服务端返回唯一Workspace与可恢复草稿：“草稿已创建” | 继续编辑、生成合同、保存退出；不表示可启动 |
| M2 合同已确认封存 | 精确接纳和整组物化回执：“合同已确认，启动条件待满足”或“合同已确认，尚未运行” | 查看合同，补齐资源和检查；确认不隐含执行 |
| M3 首次新建完成 | 封存、必需资源/创建准备、启动准入和当时有效检查均成立，且成立时没有Run：“新建完成，尚未运行” | 默认由用户点击“激活执行”；明确有界自动模式可独立提交激活 |
| M4 激活 | Run owner的真实RunActivated和runtime接纳进度；pending RunCreated只显示“已准备，待激活” | 进入Run；接纳完成后显示真实运行状态，不是目标验收成功 |

M3是历史里程碑；之后检查过期或资源掉线显示“新建已完成，当前启动受阻”，保留首次回执及其定义版本。不能把旧完成徽章贴到新草稿/新定义上冒充就绪。自动组合交互可跳过瞬间的“Run数0”展示，但最终显示真实Run与原M3因果，不能在已启动后还说当前无Run。

## 2 输入与保留规则

新建不要求用户预先写出完整技术方案、任务图或所有测试脚本。用户提供目标与资源，系统负责将其转为可审阅的候选合同；系统推断必须显式标识，不能伪装成用户原话。

| 输入 | 来源与要求 | 缺失时处理 |
|---|---|---|
| Workspace 名称 | 用户输入，可提供可编辑建议；不承担唯一身份 | 提示填写或确认建议 |
| 目标原文 | 用户必填；保留原文及来源，不静默截断 | 不允许生成可确认合同 |
| 额外验收要求 | 用户可选；与目标内隐含验收要求共同解析 | 模板可补建议，不能用模板覆盖用户要求 |
| 模板 | 用户选择，或系统给出明确可见的推荐 | 不可静默选择有额外权限/成本的模板 |
| 资源引用 | 用户提供或确认；含种类、定位、版本策略、访问用途、可读/可写边界 | 本阶段不必所有外部资源都在线；不足以理解目标时先澄清，影响执行时标注启动阻塞 |
| 交付位置 | 用户选择或确认系统默认 | 默认必须安全、可解释；不可覆盖现有文件或隐式采用服务进程任意工作目录 |
| 工作范围与禁区 | 用户约束优先，模板补全；例如不改生产库、不推送、不自动部署 | 高影响行为没有明确授权时不得从目标推断授权 |
| 预算与执行策略 | 来自可见、版本化默认值，允许用户调整 | 缺失不得被解释为无限预算；默认策略变动不能热改已确认合同 |
| 凭据 | 仅保存受控引用与适用范围，不直接进入文本合同 | 不索取明文密钥，不在 Web/客户端日志或导出包中回显 |
| requestId、修订、哈希等 | 系统生成并由owner持久保存；页面只内存携带，用户一般无需填写 | 不把技术字段变成新建向导负担 |

资源引用不是授权本身。用户选择某个仓库或目录，不等于允许删除、推送、部署或传出其全部内容。系统读取、写入、执行、网络、模型发送范围需分别表达并受既有权限边界限制。

输入原文、系统建议、模板默认和用户答复分别标注来源。未保存内容在模板查询/生成失败时仍可继续编辑；只有服务端保存回执才显示“已保存”。requestId、revision、hash由客户端/服务端合同生成并携带，用户无需填写；页面超时不能提示“换个requestId重新建”。

Web禁止用localStorage、sessionStorage、IndexedDB、cookie或其他浏览器持久机制保存业务输入、事务恢复身份、服务端数据。输入与重放payload仅保留在当前页内存；界面明确提示“未保存输入在关闭或刷新后丢失；已发送事务不会因此取消”。用户返回列表/重新打开时先查询服务端owner，不能从浏览器缓存复活旧事务。同会话失败保留输入，不等于跨刷新持久保存。

候选生成前不要求用户提供完整技术方案、任务图或未来测试脚本。资源此时可离线，先区分“不能理解目标，需要澄清”与“合同可封存，但启动受阻”。显示服务器/远端真实位置，不把浏览器本地路径当服务端路径。凭据仅安全引用，错误日志/普通合同/默认导出均不回显秘密。

## 3 向导和页面动作

Web新建向导采用以下七个逻辑步骤，允许非阻塞前进和保存恢复，但合同确认只在门禁满足后开放。

| 步骤 | 展示/输入 | 操作 | 成功出口及异常 |
|---|---|---|---|
| 1 目标与模板 | 名称、目标、模板用途/版本；展开说明和验收要求 | 下一步、保存草稿 | 必填错误就地提示；模板加载失败不丢目标原文 |
| 2 资源与边界 | 资源引用、读写范围、交付位置、预算与禁区 | 检查、返回、保存 | 显示服务器实际可访问位置；浏览器本地路径不能假装是服务端路径；凭据仅安全引用 |
| 3 生成合同 | 当前输入修订、生成进度、阶段、费用/预算提示 | 生成、停止生成、稍后继续 | 首次创建后立即给出恢复入口；超时查询原操作，不再新建 |
| 4 澄清与审查 | 阻塞问题、可见假设、要求/义务/DoD 覆盖、审查发现 | 回答、修改、重新生成、保存退出 | 回答更新修订；旧审查失效；生成失败显示可恢复原因 |
| 5 确认合同 | 完整合同与差异；目录、权限、启动阻塞；默认提示“确认不启动”，自动模式显示授权范围与政策接纳依据 | 默认确认此版/返回修改；自动模式记录精确候选接纳 | 只接纳精确当前版；越授权、UNKNOWN或实质差异暂停；不能把未来未知候选记为人工已确认 |
| 6 核对启动条件 | 合同启动准入、startupInputHash、动态能力/资源检查、必需目录及持久化完整性 | 检查、补齐、重试、保存退出 | 未满足时显示合同已确认及具体阻塞；不伪装成完整新建成功；检查不执行目标业务副作用 |
| 7 完成/进度视图 | ID、精确合同、资源/模板、产出索引、M3历史回执、当前就绪及真实Run状态 | 查看Workspace、可选导出、继续补齐；默认满足条件时点击“激活执行”；自动模式显示激活进度 | M3与M4分开；进入页面不产生新授权，获准自动流程独立提交激活意图；最终显示实际Run，不沿用过时“未启动” |

生成及用量视图须保留当前实现已有的真实语义：无Run显示“执行未启动；Result未验收”；未加载不显示零调用；部分或有界窗口不标成全历史成本。成功原文审计采用显式受控入口，不混入普通进度或自动导出。

重复点击通过操作ID/幂等键收敛，禁用按钮只是辅助。仅当前页面会话可从内存重放同一请求；刷新、后退、关闭、再次打开只能恢复服务端已保存事实，不承诺恢复未保存编辑或已丢失的页内事务身份。恢复未决事务须先通过owner查询核对；跳转必须在确认读取权威结果后发生，不由前端乐观状态决定。

步骤不要求七个独立页面；可以复用现有Modal或Workspace页，但每个动作必须对应同一公开owner结果。加载中、已保存、已接纳、正在物化、M3完成及已创建Run分别显示，不以HTTP 200或按钮被禁用推断全部成功。

## 4 合同审阅与精确确认

### 4.1 页面必须能审阅的内容

| 部分 | 必须表达的内容 | 用户如何审核 |
|---|---|---|
| 原始输入 | 原文、来源引用、资源和用户约束、输入修订 | 可查看原文及与上版差异 |
| Goal | 预期结果、适用对象、范围、明确非目标、前提假设 | 判断是否真实表达本意 |
| Requirements | 每条独立要求的稳定 ID、来源片段、优先/required 属性 | 原文逐项可反查，不只看一段摘要 |
| Obligations | 必须被证明的具体义务及其要求来源 | 检查是否遗漏最终结果或边界 |
| DoD | 条件、对象、阈值、可接受证据、验证方式、失败/未知处理 | 检查是否可判定，不能仅“质量良好” |
| 覆盖关系 | requirement→obligation→DoD；允许多对多，但每项义务保留身份 | 能看到未覆盖项，不能以共享一个 DoD 抹掉其他义务 |
| 交付物 | 类型、预期路径/位置、格式、必要完整性检查 | 明确最终会拿到什么 |
| 资源与权限 | 引用/版本、读写执行边界、网络与秘密处理、预算 | 检查系统能做什么、不能做什么 |
| 验证策略 | 自动/人工/可信外部验证条件及所需能力 | 未实现的验证能力标为阻塞，不能虚称可验收 |
| 澄清与假设 | 未决问题、系统建议、用户答复、影响范围 | 用户显式接受或修正重要假设 |
| 模板快照 | 版本、继承来源、有效配置和哈希 | 区分用户要求与模板默认 |

当前实现中独立精确Goal requirement用于保存完整来源，不能被要求凭空补造重复DoD obligation；Goal内原子承诺仍必须进入可验收义务，锚点文本不能替代语义覆盖。

新建阶段形成的是验收标准及证明义务，不是已经发生的执行证据。不能因为六个 critic 都返回 PASS，就宣称目标完成；critics 的适用要求范围和未覆盖项仍必须确定性检查。

### 4.2 手动确认动作

- 用户能从摘要展开完整原文、逐项来源、要求/义务/判据、共享覆盖理由、审查范围和未决项；摘要不能替代完整可审阅合同
- 系统标出相对上版的目标、判据、约束、资源、预算变化；用户答复形成新输入修订后，页面明确旧审查已过期
- 默认主按钮为“确认此版目标与验收合同”，旁边写明“确认后尚不执行”。按钮绑定正在显示的exact candidate revision/hash；服务端返回冲突时展示当前版与本页版差异，不能自动确认新版
- 确认中显示当前物化进度。关页、后退、断网或点界面取消不回滚已提交seal；再次打开从服务端恢复已确认/待恢复事实
- 晚到生成结果标为历史版本，不能把新版编辑替换掉。遇到部分物化/hash冲突展示恢复冲突与准确操作ID，不建议删除Workspace后重做
- 审查UNKNOWN、缺required覆盖或不支持验证能力时突出阻塞原因；不能只展示六个绿色PASS掩盖漏审。N/A显示依据，不把未审设为N/A

具体接收输入及恢复由NC00维护；本页不拥有confirmation journal或第二份合同状态。

## 5 默认手动与一次提交自动模式

### 5.1 默认手动

自动启动选项默认关闭。精确确认、准备与检查后显示M3，用户点击“激活执行”才提交精确Start意图；刷新页面、进入Workspace或确认合同均不自动授权。按钮可根据当前视图禁用，但服务端始终重查；readiness过期显示“重新检查启动条件”，不继续用旧绿灯。

### 5.2 用户明确选择自动模式

初次提交时尚无最终Definition，页面让用户明确看到并授权：原始目标/模板/资源范围、可接受候选规则、允许动作、预算/累计范围、风险边界、授权期限、一次初始激活及另需许可的操作。不得要求用户先确认未来未知hash，也不把授权与普通“保存草稿”合并。

操作文案可为“提交并在审查通过后自动启动”，附可展开授权摘要；用户明确提交后，不再要求同一授权的第二次点击。系统按NC02先检查候选是否忠实保留授权内承诺，再对exact candidate形成政策接纳回执，可靠封存并完成M3，最后派生精确激活permit。页面分别标识“人工确认”或“按授权政策接纳”，不伪造用户看过最终合同。

缺期限/预算/权限等必填且没有已批准的可见默认值时，页面只问缺少的具体授权。候选越界、UNKNOWN、授权过期/撤销、必须人决或启动检查失效，显示暂停的准确阶段和待补条件；不能自行缩小目标来凑过授权。修改已设定承诺仍按§8的ticket/最终精确approve路径。

### 5.3 撤销和手动/自动竞争

“撤销自动授权”显示服务端结果。若撤销先被接纳，提示尚未接纳的激活已停止；若本次激活已先被接纳，展示“授权已撤销；这次启动已受理”及原intent/Run，提供已有独立取消动作。不能承诺撤销按钮必然抢在启动之前，也不能把授权撤销当成Run取消成功。

自动调度与手动点击共同进入同一个initialactivation身份。即使第一个Run已快速终结，迟到点击仍打开/展示这个Run；页面重试绝不成为“再次运行”。真正再次运行必须使用明确独立动作和新的执行意图，沿现有Run合同；普通相同Definition重跑不因此强制改约。

## 6 进度和错误展示

### 6.1 必须区分的状态轴

| 页面轴 | 需要显示的服务端事实 |
|---|---|
| 创建 | WorkspaceID、创建操作ID、已提交/待恢复，是否可在列表发现 |
| 资源准备 | 必需目录/绑定/索引进度，失败资源和归属；不把用户目录内容当清理候选 |
| 合同 | input/candidate/definition版本；草稿、生成、审查、接纳、物化及seal分别展示 |
| 准入 | exact StartupInputHash与admission结果；不能用eligible代替动态就绪 |
| 动态就绪 | certificate检查时点、有效期限/规则、definition/config/resource绑定、stale/unknown原因 |
| 历史完成 | M3 completionID、完成时版本和时点，与当前readiness分开 |
| 授权/执行 | 手动待激活或有界grant范围/期限；稳定intent及真实Run状态、unknown时查询入口 |
| 用量/结果 | authoring归Workspace，Run未存在时明确未启动/Result未验收；未加载不显示0，不完整窗口不冒充全历史 |

这些都是查询投影，不向Workspace.State堆入新枚举。原文审计通过显式有权查询入口，不混入普通进度或默认导出。前置诊断另列target request/stage/phase、input/template、diagnosticID及保存完整性；展示原始bytes前核对完整身份、byteCount与SHA256，失败则拒绝显示。非UTF8保已校验原字节下载，不以替换字符冒充原文；未保存/超界/读取失败如实说明，不能把已知失败改为UNKNOWN或把partial标complete。

### 6.2 错误到可操作文案

以下NC错误名为目标合同标识，真实wire code由组件目录映射；页面不得仅显示Go内部错误或模糊“失败”。

| 结果类别 | 页面展示 | 用户可采取的下一步 |
|---|---|---|
| 输入无效/越权 | 精确字段和可理解原因；无权对象不泄露是否存在 | 修改已授权输入/重新选择资源 |
| NC_CONFLICT/草稿CAS | “内容已更新，本页版本较旧”，给可读差异 | 载入当前版并人工合并，不自动覆盖 |
| NC_REVIEW_INCOMPLETE/UNKNOWN | 漏审义务、判据、审查类型与缺证据 | 补充/澄清/重新审查；不用删除required解阻 |
| NC_MATERIALIZATION_CONFLICT | “合同已接纳，物化受阻”，区分已提交与未完成 | 从原操作恢复或交由有权人员处理；不重复签新版 |
| NC_PREPARATION_INCOMPLETE | Workspace已存在及失败目录/绑定/索引阶段 | 重试原准备操作；保留已有文件和草稿 |
| NC_READINESS_STALE | 显示哪个definition/config/resource/期限变化 | 对当前绑定重新检查；若需改约转§8 |
| NC_CAPABILITY_UNSUPPORTED/RESOURCE_UNAVAILABLE/CHECK_UNKNOWN | 具体能力/资源和影响范围，不显示“可启动” | 补齐连接/能力或保持阻塞，不承诺工具自动降级 |
| NC_AUTH_EXPIRED/REVOKED/SCOPE | 授权失效原因、是否已有Start被接纳 | 提供缺失的精确授权；已受理则查询/取消原Run |
| NC_RESULT_UNKNOWN/网络中断 | “结果待核对”，已知Workspace/intent/Run ID与最后权威阶段 | 查询原请求，不换ID重复创建 |
| NC_DECISION_STALE/ADOPTION_CONFLICT | “批准所指版本已改变，尚未应用”及差异 | 审查最终新候选并取得对应精确批准 |
| NC_HANDOFF_BLOCKED | 新合同已封存，旧Run终态/unknown效果/预算/交接哪项未满足 | 查看具体责任与对账进度；人工批准不证明旧effect没发生 |
| 导出失败 | “合同已确认，导出待重试” | 重试投影，不撤销合同/重建Workspace |

刷新、重连、返回列表及重新打开先取权威状态；若Run已存在显示该Run及当前状态。关闭页面不删除、取消或授权后台工作。停机中显示实际停止/待恢复状态，不在后台已拒绝请求时乐观显示保存成功。

## 7 Web-only入口边界

用户最新已经明确：新建只要求 Web，且不需要保留 TUI 创建入口。这是本项已确认的范围约束，不是待定选项；仍不构成当前阶段修改代码的授权。

目标方案：

1. 移除 TUI 创建菜单、帮助项、快捷键及 `/workspace create`、`/ws create` 解析入口，不保留“请使用 Web”的创建占位入口
2. 不实现 TUI 新建向导；既有仅拒绝创建的命令方法若无其他使用者，在实现评审时清理
3. TUI 现有选择/查看 Workspace、运行控制等能力保持各自原有合同，不因移除创建入口而拆除公共 authoring API
4. Web 通过同一应用/owner 公开能力创建；不能误删底层领域合同，因为该合同仍服务 Web
5. 多浏览器标签/会话仍须验证并发修改、确认与恢复；移除 TUI 不消除并发问题
6. 旧操作或未知命令不得误匹配为启动、删除等其他动作；只给通用不可用命令诊断，不新增创建兼容别名

验收需同时核对“所有创建入口确实消失”和“非创建能力没有回退”，而非仅删除一个菜单文字。

## 8 已封存合同的变更页面

变更目标、验收标准或合同约束必须从“提出合同变更”进入，展示完整原因、触发证据、before/after、备选方案、影响集、旧Run/effect/预算责任和不变更后果。普通任务分解、获准recipe、readiness重查不能被误导到改约页面。

页面次序固定为：提出reasoned ticket → 编辑候选与审查 → 审阅最终精确版本 → approve → 显示Workspace采纳/物化 → 安全交接和当前准入 → 已获授权的新Run。合同批准与执行授权可以在同一次明确提交中分别表达，例如“批准此版并按所示范围激活新Run”；仅“批准此版合同”不暗含执行。原始批准范围未变而只需恢复时，不再重复要用户批准。

必须分开显示“待决定”“已批准但未采纳”“已采纳待物化”“新合同已封存，激活受阻”“新Run已创建”。存在前驱时展示真实旧/新Run、Definition和lineage；旧terminal结果不可被新成功覆盖。无前驱则明确“尚无执行历史，将创建首个Run”，不能为版本采纳补造一个Run。旧unknown效果/预算未解决时显示责任与阻塞，不能显示已清零。

详细决议/定义采纳/terminal后继/崩溃恢复只见NC04/NC05；页面不得自行解释Decision resolved为变更已应用，或把Approval当无Run定义批准。
