## 1 阅读与完整性规则

本索引覆盖 ownership manifest 的全部29个 transition families：4个正式机器、25个支持资源/私有事务/效应门禁/投影生命周期。SM-1列出20条不同状态边；SM-2/3/4以76种具体私有事件索引，其中primary SM-2为28、SM-3为29、SM-4为19。支持事务列出97个event或明确的同事件子切点。计数不是“97个独立状态机”，也不声称每个enum值都有公开命令。

每条RT边的“前态与guard”“原子写集”“结果与拒绝/恢复”与其源代码入口共同构成合同。为避免把源代码重复粘贴成第二份实现，表中的写集列列出必须协调的账本，所链接的具体transition函数正文是字段级完整after-image和细分guard的权威展开；同表“最大写域”由穷举write-set switch原样提取，表示该event允许协调的完整SM域，并不要求每一分支都修改所有域。新增event、字段或分支必须同时核对具体函数、write-set、aggregate invariant与覆盖表，不能凭本表概括新增权限。

- RT-ID 为现有 `RuntimeInternalEvent` 去掉前缀后的名字；属于owner-private入口，不是可发布的EventHub命令
- RS-ID 的family来自manifest，后缀为实际event wire值或明确payload/事务切点；后两者在表中说明，不能当作现成DTO名字
- 跨owner输入/输出字段、schema/兼容规则在[具体合同目录](../contracts/组件具体合同目录.md)；新目标协议在[创建与定义变更合同 NC01–NC05](../contracts/创建与定义变更合同.md)
- 测试fixture/case、切点注入与pass/fail oracle唯一在[验收规格](../validation/验收规格.md)；总体G0–G4、R/C/B和现状缺口唯一在[总纲](../Workorch_逐项收口总纲与首项方案.md#gap-ledger)

### 1.1 所有Runtime边共用的前置合同

E1：WorkspaceID/RunID不可为空且必须匹配当前aggregate。恰有一种具体payload；payload family与event的映射必须精确。primary SM不等于payload family：例如OperationEvidenceObserved是transaction payload但primary为SM-2；ProviderRequestRecoveryCoordinated是transaction payload但primary为SM-4。

E2：load先验证版本、结构与完整反向lineage，破损/不兼容数据不进入reducer。request/authority/DefinitionFocus/manifest/dispatch/execution/fence必须取当前持久身份；未封存的外部target state、可执行callback、任意authority-shaped payload拒绝。

E3：读取fresh preimage；合法修改的StateRevision必须恰为expected+1，经唯一RuntimeTransitionCoordinator.Commit对完整aggregate和terminal-seal不可变约束校验后一次CAS。错误、torn shape或语义revision漂移不允许部分落地；Run物理record无关字段变更由Run存储层rebase，不解释SM-2/3/4。

E4：只有event具体replay guard已证明same payload/lineage时才返回existing/no-op。不能仅凭同EventID/RequestID略过hash、source、resolution或fence比较。冲突重复拒绝；合法stale诊断保留原stale语义且不能覆盖新authority。支持owner的某些内部marker重复会返回conflict，外层必须读原记录去重，不把“所有内部event都no-op”当源码事实。

E5：cross-owner I/O在CAS外。先持久request或成功claim，再执行已授权的唯一handoff；response loss先查询原receipt/session/ACK。旧scope、已终态、retired generation不得从重试获得新许可。通用error文本、timer、页面刷新、普通Resume均不提供恢复权限。

## 3 SM2确定性顺序与失败映射

<a id="SM2-Priority"></a>

### 3.1 裁定优先级

这是reducer优先级，不能将七个ConvergenceState任意两两互转。完整事务还须遵守SM4的terminal/termination优先lane。

1. 规范化facts，重新绑定current focus repair；退休旧focus prerequisite，保留完整pending graph
2. 若有exact governance operation continuation owner-event，先反证原granted binding、source dispatch、evidence和next fence，再派生同一sealed operation序列
3. 若适用ImplementationWork private obligation，先使用其专门reducer；当前可执行admission恒false，不据此宣称可生产执行
4. 普通reduce首先处理已有确定failure/预算处置，不能被后到freshness掩盖
5. pending prerequisites → need_prerequisite；owner repair confirmation pending只产生只读confirmation handoff，不授权candidate
6. 当前owner fact确实unavailable先收敛；已owner-grounded failure target才可need_state_change；当前action infeasible按具体code失败
7. 无provenance no-op走一次可验证观察/assessment或provenance终止；不能随机再写制造delta
8. 当前已持久RepairDirective优先于原始missing evidence或anti-replay，且只能在原closure内state_change→fresh validation
9. assessment后的owner-postcondition/acquisition耗尽先于泛化target gate；prospective owner确认目标尚不存在时先产生合法durable create
10. 全部required evidence与all-of guards齐后，必要assessment尚无则need_assessment；确定性coverage满足才settle current CWI及推进focus，所有focus/Run-level guards齐才交terminal；否则按缺state_change、缺validation、unsupported_evidence_gap次序裁定

注意：`completeOrAdvanceDecision`可先返回current-focus的complete候选，commit/drive路径必须先原子advance剩余focus；不能把这一中间返回值直接交付为Run completed。

### 3.2 失败不再用“failed或治理”占位

同名failure class只是默认分流，完整优先级以reducer和typed producer事实为准。例如`FailureClassDisposition(capability_unavailable)`的默认governance并不覆盖已证明当前action无可行recipe的terminal；不能仅用默认disposition重写上述精确分支。

<a id="HandoffBarrier"></a>

### 5.1 Workspace释放与新Run屏障

现状Workspace terminal ACK会清 `ActiveRunID`。这是ordered saga中间切点；其持久terminal fence与Run replacement记录仍限制后继。**对应Run terminal delivery/ACK未完成前，逻辑handoff屏障不能释放；不能以空slot创建或激活另一Run。** 所有启动/重启入口在同一接纳检查中核对pending activation reservation、上一代handoff、Run generation和terminal/replacement identity；新目标的reservation不是实际ActiveRunID或新SM1 enum。

新目标以NC02/NC03的Workspace原子授权消费+稳定activation intent+reservation为接纳点，Run独占物化RunID。撤销先赢不发permit；接纳先赢则已受理，撤销不得反称未受理，动态许可撤销仍阻止之后尚未授权的effect。晚到first-activation重复即使原Run已terminal也返回原Run，不能reinterpret为Restart。

Run terminal/三ACK也不证明物理未知effect已消失。NC05独占跨Run conflict scope、owner proof和解除条件：SM4协调、capability owner报告可反证receipt/reconcile/isolation事实、SM2在后继fresh workspace_full reconciliation中接受并封执行gate。无法判定冲突按可能冲突处理；无owner-supported证明就拒绝该effect，不继承前驱coverage credit。该通用跨Run门禁是目标要求，不能以本索引的现状边证明已实现。

### 8.1 尚未接纳Runtime时的行政收尾

<a id="TGT-NC03-AdministrativeCloseout"></a>

此分支是目标接线，基线没有上述新event/持久variant。NC03的PreparePendingActivationTermination只是本算法的交互别名，不另立收尾机。严格顺序：

1. Run先持久明确取消intent，绑定原ActivationIntent/Permit/RunID/generation、reservation、合法取消来源及reason。合法来源只限显式Cancel或已冻结policy对该精确撤销事实的取消映射；普通资源/准入失败仅保typed诊断并blocked，不制造cancelled/failed。无SM2 sealed failure就没有failed授权
2. 已有可读完整Runtime aggregate时，沿RT-TerminationRequested与既有seal/ACK路线；若Run已经active但尚未建立aggregate，也不能要求先调用provider或强行正常执行初始化才能取消
3. 无aggregate路线不能以NotFound、空列表、未收到回执或Run是否active单独证明零effect。Run/Orchestrator必须在同Run initialization/dispatch writer fence下反证原birth record、初始化提交标记/opaque generation、authoritative dispatch/claim inventory与operation授权均未越过业务handoff点。该目标证明形状及fence要持久可查，不由UI或缓存提供
4. 证明齐备后，以expected Runtime revision=0和同一fence CAS写administrative-only上下文：原Run/Workspace/Definition/startup/bootstrap hash、Run取消intent identity、permit/reservation/generation、源授权/撤销fact refs、原预算责任refs、零业务dispatch的owner证明。此variant只属于SM4收尾域，不填造SM2 Decision/Authority或SM3 session/attempt/evidence/credit；一经建立永不转成普通业务Runtime
5. 若并发正常初始化先commit，admin CAS失败后fresh-load原aggregate，再走步骤2；若admin CAS先赢，正常初始化必须识别administrative-only fence并拒绝开启业务。无法证明未提交、owner inventory失败或数据不一致时返回typed administrative-closeout blocked，Run/Orchestrator保留原责任和可重试对账义务；不放reservation、不调用provider、不改成terminal。结构损坏/未知版本继续load fail closed，只能明确运维修复，不用此路径掩盖
6. SM4由该context与Run取消intent生成明确行政terminal source，先保存TerminationRecord，再由目标扩展的纯material compiler独立CAS封material seal。现行RuntimeTerminalDeliveryFact/Run guard需要SM2 snapshot及opaque fence，因此目标协议必须增加版本化 `RunAdministrativeIntent` source variant和对应Result/Workspace/Run校验，不能伪造AuthoritySnapshotID/EvidenceRevision以满足旧校验。只交付cancelled事实、未完成的原义务和真实预算责任；不补success/credit
7. 仍严格Result ACK→Workspace ACK→Run exact terminal ACK；前者的中间空ActiveRunID不解除reservation/handoff。SM1合法出口分别为R1-TerminalDelivery.PX或AX，绝不先强行active/回pending。原ResultID、seal/hash、取消intent和orderedACK丢响应复用；只有exact终态/ACK后才解除该intent的活动资格屏障

正常execution的ValidateExecutableAdmission保持原gate；行政-only支持只豁免“为了取消必须先准许业务执行”的错误依赖，不给任何业务provider/能力effect权限。版本化opaque variant、terminal identity/material compiler、Run guard和三个owner ACK需同批合同/兼容验收，旧版不识别就拒绝，不能混版伪成功。
