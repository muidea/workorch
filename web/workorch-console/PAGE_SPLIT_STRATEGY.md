1. 从简单到复杂，逐步拆分
2. 每次拆分后立即验证构建
3. 辅助函数保留在 main.tsx 中，避免循环依赖
4. 只拆分页面组件本身，不拆分内部子组件

**阶段划分：**

### 方案 B：保守拆分（备选）

只拆分简单页面（阶段 1），保留复杂页面在 main.tsx 中。

**优点：**
- 风险低，易于验证
- 减少约 10% 的代码量

**缺点：**
- 改进有限
- main.tsx 仍然很大（6535 行）

## 关键技术点

### 1. 避免循环依赖

**问题：**
- 页面组件使用辅助函数
- 辅助函数可能被多个页面共享
- 如果提取辅助函数到独立文件，可能导致循环依赖

**解决方案：**
- 辅助函数保留在 main.tsx 中
- 页面组件从 main.tsx 导入辅助函数
- 或者将辅助函数提取到独立的 helpers.ts 文件

### 2. 类型定义管理

**策略：**
- 共享类型定义保留在 types.ts
- 页面特定的类型定义（如 FormValues）移到页面文件内部
- 避免在页面文件中重新定义已有类型

### 3. 内部子组件处理

**策略：**
- 如果子组件只被一个页面使用，移到页面文件内部
- 如果子组件被多个页面共享，提取到 components 目录
- 例如：SoulDefinitionManager 只在 ConfigurationPage 中使用，移到页面内部

### 4. 验证流程

每次拆分后必须执行：
1. `npm run build` - 验证 TypeScript 编译
2. 检查 main.tsx 行数变化
3. 检查是否有未使用的导入
4. 提交 git commit

## 风险评估

### 高风险点
1. **WorkspaceDetailPage** - 代码量大，依赖复杂
2. **辅助函数依赖** - 可能导致循环依赖
3. **类型定义冲突** - 可能需要重新组织类型

### 降低风险的措施
1. 每次只拆分一个页面
2. 立即验证构建
3. 使用 git 版本控制，随时可以回滚
4. 保留辅助函数在 main.tsx，避免复杂的依赖重组
