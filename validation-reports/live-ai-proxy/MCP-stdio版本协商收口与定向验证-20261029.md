## 实现范围

- MCP owner `pkg/protocol` 明确支持 `2024-11-05`、`2025-11-25`；请求首选仍为后者，不按日期区间自动接受版本。
- Runtime stdio 校验初始化响应 envelope 和返回版本；保存实际协商版本及原 result 于进程私有 session，
  然后才发送 initialized、执行原授权业务 operation。
- preparation v2 的 producer 和消费者共用上述版本规则；未知版本保留 `protocol_version_unsupported`，
  缺失/畸形初始化保留 `protocol_failed`。均关闭进程，不继续 initialized/list，原回包不改写。
- v1 仅校验/回放原记录，冻结原精确判定；新观察入口拒绝 v1。新显式检查使用 v2，原 blocked 记录不升级，
  不补 completion，不在 query/recover 时重新握手。
- 正常关闭、完整能力、分页拒绝、Registry/scope/directory、预算、重复和 owner 边界保持。
  三种 list 及三类业务 operation 都在两种协议 fixture 下验证；额外未选中工具不阻塞选择集合。

Runtime 只涉及 MCP capability 在 SM-3 sealed dispatch 后的执行与 SM-4 返回/排空参与；
没有改动 SM-1～SM-4 的 reducer、aggregate、credit、grant、预算或迁移，也未新增运行单元。
跨 owner concrete EventHub 合同仍由原 owner 定义。preparation 独立于 Runtime 执行。
