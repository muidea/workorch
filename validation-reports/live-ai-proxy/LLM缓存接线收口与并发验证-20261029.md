# LLM 缓存接线收口与并发验证（2026-10-29）

## 结论与范围

Workorch 侧 STEP02 authoring 的共享快照分区、Responses typed 消息、显式缓存身份及断点、读写用量 presence 和 Web 展示已接通，相关无收费回归通过。支持不同 Workspace 使用完全不同的开发资料并发请求，不依赖业务内容相似，不跨 Workspace 复用答案或事务状态。

本轮未调用真实收费模型、启动 Run、修改用户配置或部署服务。没有改变 Runtime SM-1～SM-4 的状态迁移、执行授权、准入、预算或人工确认；新的消息布局仅由 authoring 显式选择，既有 Runtime scalar wire 保留。不能据此宣称全 CI、真实缓存命中或部署验收通过。

当前 AetherRelay 已核对的 Codex adapter 会移除 `prompt_cache_options` 及 input content 的显式 breakpoint；本轮未修改网关。实际远端 route、版本和转发行为仍需观察，网关若使用该路径，应先保留或支持这些缓存语义，再验证真实命中。

## 已完成实现

1. authoring 使用 `section_messages/v1`。六审共享 C0 固定合同、C1 完整规格快照和 C2 完整 Profile 声明；各自审查种类、要求及 wire 合同留在 C3。保留全部原始业务字段，业务资料保持 user 角色，六审仍独立。
2. Responses adapter 发送真实 typed messages、`prompt_cache_key` 和显式模式，在最后一个连续共享段末端设置 breakpoint。没有通过填充 prompt、改变 TTL、减少六审或重试降级争取命中。
3. 缓存身份绑定 Workspace、实际 provider/model、schema/format、reasoning 及真实渲染前缀（含角色、内容与断点）。requestID、审查种类和时间不影响同一共享前缀身份；内容变化改变身份。即使两个 Workspace 文本相同，其 key 也隔离。调用方传入的 hash 不作为缓存身份权威。
4. owner 为每个请求独立维护预算、缓存计划和审计；实际 wire 总字节仍受原配置上限约束。没有新增全局可变会话或本地答案缓存，不跨 Workspace 共享 Goal、DoD、候选、历史或用量。
5. 原生 `cached_tokens` 与 `cache_write_tokens` 区分缺失、null、明确零和正数。缺失显示未知；部分调用缺失时展示已知部分，并避免生成完整命中比例。旧记录中的零不倒推为已知零。
6. 更新 authoring mock/verifier、相关 integration fixture 和组件 readme，兼容旧 scalar fixture。生产 Web assets 已重新构建。
