# STEP04 Web 完成身份零值编码收口（2026-10-29）

## 结论与范围

已修复上一轮生产 Web 的“准备完成身份无效”：Go 管理 DTO 的 `PreparationEpoch uint64` 使用 `omitempty`，省略首次合法值 0；Web 严格 completion 校验因此拒绝真实响应。本轮改为始终编码 `preparationEpoch`，同步现行 HTTP 合同，保留前端严格校验。

生产修改仅涉及公共 DTO 的 JSON 表达，不变更 Workspace 持久格式、epoch 含义、M3 裁决、过期窗口或 owner 边界。Runtime SM-1～SM-4 的状态及迁移均未改变。未更改 Web 生产代码或生成 assets。

代码与本地回归已完成；本轮没有部署、重启或修改 8090 服务，没有启动 Run 或调用真实推理／embedding。**部署后的实际浏览器只读复验仍待执行，不能将本报告记为完整 live 或全 CI 通过。**

## 回归覆盖

- 抽取已有 typed completion fixture，由真实 Go `json.MarshalIndent` 编码生成合成 JSON，逐字节对比编码结果。该 fixture 不含真实业务材料或配置，并同时供 HTTP 和 Web 测试消费，防止手填前端默认值掩盖 wire 错误。
- HTTP 使用正式路由测试 GET、check、recover，覆盖 completed+observed 与 completed+stale 共六种组合；直接检查原 JSON 属性为数字 0，避免反序列化到 Go uint64 后把缺失值误认为合法零。
- Web 使用共享 JSON 验证、挂载准备页，保留历史 M3、currentValidity 和后续 Run 的独立展示，且不自动检查、恢复或创建执行。
- 反例继续拒绝 epoch 缺失、null、非零，以及错误 completion hash/request/expiry、重复或缺失 completion、伪造 assessment。
