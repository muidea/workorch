### 普通开发及来源边界

核心只识别能力 owner 的 selector、operation、variant 和约束组合，不增加语言、Go 测试框架或 AI Proxy 业务常量。默认不强制两轮或故意失败；Goal、综合交付及其他 Profile 不因软件开发声明获得普通文件修改权。

新默认选择已有 Shell `/v8` 四阶段合取与 input-consistency `/v3` 消费者，保留完整独立审查与多失败源归属。旧 template 指纹已登记，已封存 Workspace 不热升级。旧输入存在不意味着合格，冲突仍不授予写权限。

公开 fullflow 原 Goal、两项用户 DoD、13 项模板 DoD、两轮真实工作、真实失败/修复、Git/Result/三 ACK 与十分钟判据均保留。项目独有 typed consumers 在创作和确认前经公开 HTTP 模板入口声明，未私造 Run、bootstrap、receipt、binding 或 credit。

发现并修复 public 模板规范化将一个 source-bound DoD 的分号/Markdown 拆成多来源的问题；精确 source inventory 保持全文、顺序和重复项，返回值 detached。未绑定的自由文本仍沿既有规范化入口；非法 source 声明不因保真而获准入。

### 缓存边界

旧 namespace 纳入完整动态 schema，使同一 Workspace 的 manifest/step/batch 变化拆开缓存身份。本轮仅对完整匹配 LLM owner 已知 C0 ID/role/content、布局和 prompt 协议的 Runtime 请求选择稳定 family；未知或变造合同仍绑定完整 schema。调用者 hash 不作为成功凭据。

strict provider schema、当前 manifest/CWI/batch 的本地反证、物理调用和 usage 分账不变。HTTP streaming/nonstream 都使用真实配置的 provider/model/schema 能力。四个内容完全不同的 Workspace 各六次并发请求，覆盖 authoring/runtime family × streaming/nonstream，核对 exact schema/tail 配对及 usage 隔离；race 通过。相同 namespace 是 provider 路由提示，不是结果缓存、执行权或上游必然命中的证明。

### 四状态机及只读编译

SM-1 生命周期与 Run CAS 不变。SM-2 仍独立封存 working purpose/binding、审查、证据和适用性观察；SM-3 仍进行 owner feasibility、candidate、sealed dispatch 和真实 effect；SM-4 仅减少同一次适用性只读编译对同一完整前像的重复遍历。

`CompileRuntimeEvidenceApplicabilityRead` 同时产生 request 与 detached 原 receipt 读取来源。公开独立入口各自完整 Validate；私有 continuation 只有固定的完整门禁调用链，无成功标志、会话出口或结果缓存。File/Shell 仍独立核验原 receipt/key/fence，观察写入仍重查当前来源和 CAS。首错、篡改、返回隔离、恢复/CAS 前后故障和结构边界回归通过。本轮未扩大历史纯编译白名单、128 条上限或跨重启复用。
