## 本轮修改

### Appservice 测试准备

`test_helpers_test.go` 的 owner 查询有意只返回公共 DTO，不包含 `PreparationFence`。
旧 helper 将该投影应用模板后直接 Update 到测试仓库，触发了禁止删除 creation identity 的正确门禁。
现在 file-backed fixture 从完整持久前像读取，再准备原模板数据及写入。仅修改测试准备；
没有将私有字段加入公共 DTO、放宽仓库校验或新增生产跨 owner 仓库访问。
该 helper 仍是显式测试 seed，不是公开创作验收。

完整 Appservice 包通过，38.101 秒；原 52 项业务断言重新可达，没有删除、Skip 或修改业务期望。

### 真实 owner 交接屏障测试

`runtime_execution_handoff_barrier_test.go` 在首次 Create 前提供当前 fixture 的合法 creation identity；
`run_owner_dependencies_test.go` 透传底层完整原回执 reader，不从普通 Run 列表推断响应，缺少 reader 仍 conflict。
保留原请求首激活、终态交接响应丢失、两次 owner 重开、零额外 Run，以及原 Runtime／Result／seal／ACK 断言。

旧竞争请求断言还假设重启后再次转发并再次 conflict。现行 reservation 协议要求首次转发错误且无原回执时保留 pending，
重启只查询原回执并返回 exact unknown。测试分别核验首次真实 conflict、第二次原 unknown、pending 完整身份不变、
epoch=2／settled=1，以及 Run inventory／replacement／Runtime 原值不变；不将 unknown 当成功或确定拒绝。

只变更测试代码，生产 SM-1～SM-4、Workspace reservation、Run receipt 与交付合同均未修改。

### CI 失败输出

`verify-workorch-managed-full.sh` 原失败分支只打印 head/tail，中部失败被大段成功日志和 timeout stack 淹没。
现在另行打印完整日志的失败标记行号，包括 Go 用例／包失败、panic、fatal error 和编译包标记。
每个标记后最多打印 8 行上下文，以呈现断言、编译原因和 timeout running-tests 时长；最多 80 个标记，
超出时明确提示剩余数量及完整日志位置。完整原日志不改写、不截断，原退出码不变。
该索引只用于定位，不改变测试结论或业务门禁。
