## 本次完成

补齐 Application → Workspace → Soul/Skill/Memory/MCPRegistry 最终观察链，复用现有 concrete typed query，
没有新增 topic、运行单元或公共 HTTP 请求字段。File 仍由 Workspace 按原合同最终重观察。

1. Workspace 首次 accepted CAS 固定 owner-revalidation v1；原身份、revision、hash 和版本在后续迁移中不可更换。
2. 四类原来源齐全且 Memory 带原模式时，在原请求的既有 deadline 内再读各 owner。原来源不足时保留原阻塞，
   不为填充结构重做已失败查询。最终读取不执行 SkillHub status，不刷新目录、连接 MCP、推理或 embedding。
3. 完整最终原值深拷贝，经内部 settlement 随 seal 在同一 blocked CAS 保存；缺少完整最终观察以 nil 表示，
   不当成空库存、匹配或权限。原 archive 与最终 archive 分别保留；现有 seal 大小上限未放宽。
4. 消费者精确反查唯一原 archive、Workspace/request/payload/revision，完整比较 epoch、内容、配置/模式及选择来源，
   只排除观察时间差异。完整原来源已保存但最终值缺失、漂移、时钟回退或最终观察开始满 30 秒均投影 stale。
5. GET、重复 check、显式 recover 不重做四 owner 观察、不续期、不改历史逐项结论。旧操作不补挂版本。
   公共 HTTP 不增加最终原值、诊断、内部合同版本或 caller PASS 参数；内部编译 source 保持完整值及 clone 隔离。

这次变化属于 Workspace owner-private preparation 协调，不改变 Runtime SM-1～SM-4、Run 执行授权或 STEP05。
它只补已知漂移及观察年龄消费，不能把时点匹配当持续有效租约、全资源 readiness 或 M3。

File/Run 文档纠偏及字段充分/必要规则一并保留；未无依据删除 identity、revision、hash、fence 或原材料字段。
